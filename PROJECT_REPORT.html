ABSTRACT

Campus recruitment represents one of the most critical annual operations in engineering colleges, facilitating the transition of final-year students into corporate engineering careers. Despite its importance, many college Training and Placement (T&P) cells continue to manage recruitment drives through fragmented Google Forms, paper logbooks, and complex spreadsheets. This manual paradigm creates severe bottlenecks: ineligible candidates apply by mistake, placed students hoard multiple job offers preventing unplaced peers from securing jobs, multi-stage interview tracking is uncoordinated, and compiling institutional placement metrics takes days of manual effort.

To address these challenges, this project presents the Campus Placement Drive & Job Application Portal, a desktop software application engineered in Java using standard Java Swing (AWT / JFC) and lightweight CSV-based persistence. The system is designed with a strict 4-tier modular division across 4 students:

  • Module 1 (Student 1 - Lead): Candidate & Company Registry managing student records (USN, name, branch, CGPA, backlogs, skills) and recruitment drives (CTC, cutoffs, roles, dates).
  • Module 2 (Student 2): Automated Eligibility Engine enforcing CGPA cutoffs, backlog limits, branch whitelists, and an institutional Dream Company 1.5x Upgrade Rule.
  • Module 3 (Student 3): Multi-stage Recruitment Pipeline tracking candidates across 7 stages (APPLIED → SHORTLISTED → ONLINE_TEST → TECH_ROUND → HR_ROUND → OFFERED) with automated student offer synchronization.
  • Module 4 (Student 4): Executive Swing GUI, Placement Analytics (highest/average CTC, branch-wise percentages), and one-click CSV export for Microsoft Excel.

The entire system runs 100% offline from a single executable JAR file with zero database configuration, providing a dependable, fast, and academically authentic project demonstration platform.

CHAPTER 1: INTRODUCTION & PROBLEM FORMULATION

1.1 Background & Motivation

In undergraduate engineering education, campus recruitment drives organized by the Training and Placement (T&P) cell are the primary avenue for graduating students to secure employment in multinational software corporations, product startups, and core engineering enterprises. In a typical institution with 500 to 1,500 students spanning Computer Science, Information Science, Electronics, and Mechanical Engineering, recruitment involves dozens of visiting corporate recruiters with differing eligibility cutoffs, backlog allowances, and interview stages.

1.2 Problem Statement

Traditional reliance on spreadsheets and survey forms causes persistent administrative problems:

  • Eligibility Errors: Students with active backlogs or low CGPA apply without qualification, embarrassing the college during company screenings.
  • Offer Hoarding: Students who already hold job offers apply for similar low-tier drives, denying unplaced students fair opportunities.
  • Interview Pipeline Opacity: Coordinators lack real-time visibility into which candidates have cleared coding assessments, technical interviews, and HR discussions.
  • Manual Reporting Delay: Calculating institutional metrics (placement rate, median package, branch-wise statistics) requires hours of tedious manual spreadsheet work.

1.3 Project Objectives

  • Build an interactive Java Swing desktop application that operates completely offline.
  • Automate real-time candidate qualification checks with visual pass/fail audits.
  • Enforce an anti-hoarding Dream Company 1.5x Rule.
  • Provide a 7-stage recruitment tracking workflow with automatic placement status synchronization.
  • Compute institutional placement metrics and support one-click CSV export for Microsoft Excel.

CHAPTER 5: DETAILED IMPLEMENTATION BY MODULE

5.1 Module 1: Student & Company Profile Registry (Student 1 - Lead)

• Classes: Student.java, CompanyDrive.java, DataStore.java, StudentPanel.java, DrivePanel.java
• Implementation: Formulates core entity models, handles CSV reading/writing, and implements searchable tabular views using TableRowSorter. Pre-seeded realistic student records and top-tier company drives.

5.2 Module 2: Automated Eligibility Engine (Student 2)

• Classes: EligibilityService.java, EligibilityPanel.java
• Implementation: Implements 4-factor eligibility verification:

  • CGPA Cutoff: student.getCgpa() >= drive.getMinCgpa()
  • Backlog Limit: student.getActiveBacklogs() <= drive.getMaxBacklogs()
  • Branch Whitelist: drive.getEligibleBranches().contains(student.getBranch())
  • Dream Company Rule: If placed, drive.getCtcLpa() >= 1.5 * student.getPlacedPackageLpa()

5.3 Module 3: Recruitment Pipeline & Interview Tracker (Student 3)

• Classes: Application.java, PipelinePanel.java
• Implementation: Manages candidates across 7 progression stages. Includes an automated offer synchronization trigger: transitioning an application to OFFERED immediately marks the candidate as PLACED, stores company details, and saves the record.

5.4 Module 4: Swing GUI Integration & Analytics (Student 4)

• Classes: AnalyticsService.java, DashboardPanel.java, ReportPanel.java, MainFrame.java, Main.java
• Implementation: Orchestrates the primary JTabbedPane window with native look-and-feel. Computes university KPIs (placement percentage, average/highest CTC, branch distribution) and generates Excel-compatible CSV exports via JFileChooser.

8.2 Viva-Voce Q&A Cheat Sheet

For Student 1 (Profile & Drive Management):
Q: Why use CSV rather than MySQL or SQLite?
A: For an engineering mini-project, portability and zero-configuration are critical. MySQL requires external server services and configuration that often break on external examiner laptops. CSV flat files provide human-readable, reliable persistence handled natively by Java without setup friction.

For Student 2 (Automated Eligibility Engine):
Q: What is the Dream Company 1.5x rule?
A: To prevent offer hoarding where placed candidates monopolize lower-tier drives, our policy restricts placed candidates to new drives offering at least 150% of their current package (New CTC >= 1.5 * Current CTC).

For Student 3 (Recruitment Pipeline):
Q: How does automated offer synchronization work?
A: When an application is moved to OFFERED in PipelinePanel, the system automatically marks the candidate as PLACED, assigns the hiring company and package in DataStore, and saves the updated state to disk.

For Student 4 (GUI & Analytics):
Q: How is the GUI organized in Java Swing?
A: The application uses a JFrame containing a JTabbedPane organizing six functional views. The interface runs on the Swing Event Dispatch Thread (EDT) using SwingUtilities.invokeLater() to guarantee thread safety and responsive operation.
